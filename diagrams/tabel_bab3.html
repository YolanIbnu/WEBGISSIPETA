3.4.2 Class Diagram

Tabel 3.2 Atribut dan Operasi Kelas User (Tabel profiles)

No Nama Atribut Tipe Data Keterangan
1 id UUID Primary Key, Foreign Key → auth_users.id
2 username String Unique, NOT NULL
3 full_name String Nama lengkap pengguna
4 avatar_url String URL foto profil pengguna
5 role Enum Peran pengguna: admin atau staff (CHECK constraint)
6 created_at DateTime Waktu pembuatan akun

3.5 Perancangan Basis Data

Tabel 3.6 Struktur Tabel profiles

No Nama Kolom Tipe Data Constraint Keterangan
1 id UUID PRIMARY KEY, FOREIGN KEY → auth_users.id Identifikasi unik pengguna, merujuk ke tabel autentikasi Supabase
2 username TEXT UNIQUE, NOT NULL Nama pengguna yang unik untuk identifikasi
3 full_name TEXT - Nama lengkap pengguna
4 role TEXT CHECK (admin, staff) Peran pengguna dalam sistem
5 avatar_url TEXT - URL foto profil pengguna
6 created_at TIMESTAMPTZ DEFAULT NOW() Waktu pembuatan akun
7 updated_at TIMESTAMPTZ DEFAULT NOW() Waktu pembaruan terakhir

Tabel 3.7 Struktur Tabel stok_kayu

No Nama Kolom Tipe Data Constraint Keterangan
1 id TEXT PRIMARY KEY Identifikasi unik blok kaveling
2 zone TEXT NOT NULL Zona lokasi blok kaveling
3 tpk_name TEXT - Nama TPK tempat blok berada
4 wood_type TEXT NOT NULL Jenis kayu yang tersimpan
5 volume NUMERIC DEFAULT 0 Volume kayu dalam satuan m³
6 log_count INTEGER DEFAULT 0 Jumlah batang kayu
7 grade TEXT - Grade kualitas kayu
8 status TEXT CHECK (Available, Sold) Status ketersediaan blok kayu
9 updated_by UUID FOREIGN KEY → auth_users.id ID pengguna yang melakukan pembaruan
10 coordinates JSONB - Koordinat poligon blok dalam format GeoJSON
11 tanggal DATE DEFAULT CURRENT_DATE Tanggal pembaruan data stok
12 created_at TIMESTAMPTZ DEFAULT NOW() Waktu pembuatan data
13 updated_at TIMESTAMPTZ DEFAULT NOW() Waktu pembaruan terakhir

Tabel 3.8 Struktur Tabel stok_kayu_history

No Nama Kolom Tipe Data Constraint Keterangan
1 id BIGSERIAL PRIMARY KEY Identifikasi unik riwayat, auto increment
2 block_id TEXT FOREIGN KEY → stok_kayu.id Referensi ke blok kaveling yang diubah
3 zone TEXT - Zona blok saat perubahan
4 tpk_name TEXT - Nama TPK saat perubahan
5 wood_type TEXT - Jenis kayu saat perubahan
6 volume NUMERIC - Volume kayu saat perubahan (m³)
7 log_count INTEGER - Jumlah batang kayu saat perubahan
8 grade TEXT - Grade kualitas kayu saat perubahan
9 status TEXT - Status blok saat perubahan
10 updated_by UUID FOREIGN KEY → auth_users.id ID pengguna yang melakukan perubahan
11 tanggal DATE DEFAULT CURRENT_DATE Tanggal perubahan data
12 created_at TIMESTAMPTZ DEFAULT NOW() Waktu pencatatan riwayat

Tabel 3.9 Struktur Tabel system_settings

No Nama Kolom Tipe Data Constraint Keterangan
1 id INTEGER PRIMARY KEY, DEFAULT 1 Identifikasi unik, hanya satu baris (singleton)
2 tpk_name TEXT NOT NULL Nama TPK
3 location TEXT NOT NULL Lokasi TPK
4 capacity TEXT NOT NULL Kapasitas daya tampung TPK
5 total_area TEXT DEFAULT '250 Hektar' Luas total area TPK
6 zones TEXT DEFAULT 'Zona A, Zona B' Daftar zona yang tersedia
7 updated_by UUID FOREIGN KEY → auth_users.id ID Admin yang melakukan pembaruan
8 updated_at TIMESTAMPTZ DEFAULT NOW() Waktu pembaruan terakhir

3.7 Rencana Pengujian Sistem (Black Box Testing)

Tabel 3.10 Skenario Pengujian Modul Autentikasi

No Skenario Pengujian Data Masukan (Input) Hasil yang Diharapkan (Expected Output)
1 Login dengan akun Admin yang valid Email dan password Admin yang terdaftar Berhasil masuk ke Dashboard dengan akses penuh (Edit Stok, User Management, Pengaturan Sistem)
2 Login dengan akun Staff yang valid Email dan password Staff yang terdaftar Berhasil masuk ke Dashboard dengan akses Edit Stok, tanpa User Management dan Pengaturan Sistem
3 Login dengan email yang tidak terdaftar Email yang belum terdaftar di sistem Menampilkan pesan error "Email tidak ditemukan"
4 Login dengan password yang salah Email valid dengan password yang salah Menampilkan pesan error "Password salah"
5 Login dengan kolom kosong Kolom email dan/atau password dikosongkan Menampilkan pesan validasi "Kolom wajib diisi"
6 Logout dari sistem Klik tombol Logout Sesi dihapus, pengguna di-redirect ke halaman Login
7 Mengakses halaman tanpa login Mengakses URL Dashboard tanpa sesi aktif Pengguna di-redirect ke halaman Login

Tabel 3.11 Skenario Pengujian Modul Dashboard

No Skenario Pengujian Data Masukan (Input) Hasil yang Diharapkan (Expected Output)
1 Menampilkan ringkasan dashboard Pengguna berhasil login dan masuk ke Dashboard Kartu informasi Total Blok, Volume, Jumlah Log, dan Rasio Status (Available/Sold) ditampilkan
2 Validasi data dashboard terhadap database Data statistik pada Dashboard Data yang ditampilkan sesuai dengan data di database Supabase
3 Pembaruan realtime pada dashboard Data stok diubah oleh pengguna lain Kartu informasi dashboard diperbarui secara otomatis tanpa reload

Tabel 3.12 Skenario Pengujian Modul Peta Inventori

No Skenario Pengujian Data Masukan (Input) Hasil yang Diharapkan (Expected Output)
1 Menampilkan peta WebGIS Membuka halaman Map Inventory Peta Leaflet.js ditampilkan dengan poligon GeoJSON blok kaveling
2 Klik poligon blok kaveling Klik pada poligon di peta Popup detail blok muncul (ID, Zona, Nama TPK, Jenis Kayu, Volume, Log, Grade, Status)
3 Admin klik poligon blok Admin mengklik poligon di peta Tombol "Edit" muncul pada popup detail blok
4 Staff klik poligon blok Staff mengklik poligon di peta Tombol "Edit" muncul pada popup detail blok (sama seperti Admin)
5 Pewarnaan poligon berdasarkan status Data status blok di database Poligon berwarna hijau untuk status Available dan merah untuk status Sold

Tabel 3.13 Skenario Pengujian Modul Edit Stok Kayu

No Skenario Pengujian Data Masukan (Input) Hasil yang Diharapkan (Expected Output)
1 Membuka modal edit data stok Klik tombol "Edit" pada popup detail blok Modal formulir edit terbuka dengan data stok terkini terisi otomatis
2 Menyimpan data stok yang valid Mengisi semua kolom formulir dengan data valid dan klik "Simpan" Data berhasil disimpan, notifikasi "toast" sukses muncul, modal tertutup
3 Menyimpan data dengan kolom kosong Mengosongkan kolom wajib dan klik "Simpan" Menampilkan pesan error validasi pada kolom yang kosong
4 Menyimpan data dengan tipe tidak valid Mengisi kolom Volume dengan huruf (bukan angka) Menampilkan pesan error validasi tipe data
5 Membatalkan edit data stok Klik tombol "Batal" pada modal edit Modal tertutup tanpa perubahan data
6 Verifikasi pencatatan riwayat otomatis Menyimpan perubahan data stok yang valid Entri riwayat baru tercatat secara otomatis di tabel stok_kayu_history
7 Pembaruan realtime setelah edit Admin/Staff menyimpan perubahan data stok Pengguna lain menerima pembaruan data secara otomatis tanpa reload

Tabel 3.14 Skenario Pengujian Modul Data Stok dan Riwayat

No Skenario Pengujian Data Masukan (Input) Hasil yang Diharapkan (Expected Output)
1 Menampilkan tabel data stok kayu Membuka halaman Data Stok Tabel data stok seluruh blok kaveling ditampilkan secara lengkap
2 Menampilkan tab riwayat perubahan Klik tab "Riwayat" pada halaman Data Stok Tabel data historis perubahan stok ditampilkan
3 Validasi konsistensi data Membandingkan data pada tabel dengan database Data yang ditampilkan sesuai dan konsisten dengan data di database

Tabel 3.15 Skenario Pengujian Modul Laporan

No Skenario Pengujian Data Masukan (Input) Hasil yang Diharapkan (Expected Output)
1 Menampilkan halaman laporan Membuka halaman Laporan Halaman laporan ditampilkan dengan filter bulan tersedia
2 Filter laporan bulan yang berisi data Memilih bulan yang memiliki data riwayat perubahan Tabel laporan riwayat stok ditampilkan sesuai bulan yang dipilih
3 Filter laporan bulan yang kosong Memilih bulan yang tidak memiliki data riwayat Menampilkan pesan "Tidak ada data untuk bulan ini"
4 Export laporan ke Excel Klik tombol "Export Excel" setelah filter bulan File laporan_stok_[bulan].xlsx berhasil diunduh

Tabel 3.16 Skenario Pengujian Modul Pengaturan Sistem

No Skenario Pengujian Data Masukan (Input) Hasil yang Diharapkan (Expected Output)
1 Menampilkan halaman pengaturan Admin membuka halaman Pengaturan Sistem Formulir pengaturan ditampilkan dengan data terkini (Nama TPK, Lokasi, Kapasitas, Luas Area, Zona)
2 Menyimpan perubahan pengaturan Admin mengubah data pengaturan dan klik "Simpan" Data berhasil disimpan, notifikasi "Pengaturan berhasil disimpan" muncul
3 Staff mengakses halaman pengaturan Staff mencoba membuka halaman Pengaturan Sistem Akses diblokir, Staff di-redirect atau menu tidak ditampilkan
4 Pembaruan realtime pengaturan Admin menyimpan perubahan pengaturan Seluruh pengguna menerima pembaruan pengaturan secara otomatis
